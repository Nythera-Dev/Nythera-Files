# Native archive backend

Nythera Files can build the Stage 1 backend with `-Darchives=enabled`, or omit it with `-Darchives=disabled`. The default detects libarchive 3.4.0 or newer, zlib 1.2.3 or newer, and liblzma 5.0.0 or newer through pkg-config. The libarchive floor includes the RAR5 reader and the raw and Zstandard APIs. Format and compression presets still depend on the library's enabled codecs. Ordinary operations use native filters. Password-protected 7z creation and extraction use the optional system 7-Zip executable.

The backend creates and extracts ZIP, 7z, TAR, TAR.GZ, TAR.XZ, TAR.ZST, TAR.BZ2, and standalone gzip. Unencrypted single-volume RAR4 and RAR5 are read-only. Standalone gzip represents one regular file and derives its output name from the gzip suffix. Recognised suffixes must agree with the archive detected by the reader. A zlib decoder validates every gzip frame's CRC and ISIZE. Extraction stages decoded data once and validates the archive before publishing it.

Extraction writes a private tree on the destination filesystem. It estimates storage from member sizes and stored sparse extents and checks writes and closes before publishing. Each source revision check compares filesystem identity, mode, size, and modification time. A ctime-only update can occur when NFS refreshes attributes on a newly created archive and does not invalidate extraction.

Publication moves complete staged trees into place. It uses atomic no-replace rename when available and falls back to a vacancy check followed by ordinary directory rename on filesystems such as NFS. In the fallback, a concurrent empty directory created between the check and rename can be replaced. Conventional conflicts use Skip, Rename, compatible Replace, directory Merge, or Cancel. Relative symbolic links retain their archive contents, and hard links are materialised within the private stage. Successfully published entries remain available after cancellation or a later publication failure.

The Files operation manager runs compression and extraction on its existing workers and holds mount protection through staging cleanup. Archive jobs report bytes processed and entries encountered through JobView, with unknown totals during streaming. Pause and cancellation take effect at checkpoints. Publication results record the paths actually written, including renamed outputs, for completion reporting and filesystem refresh.

Compress and Extract are available from the selection context menu and the Tools menu. Compress To can select a format, method, compression preset and, where supported, password protection. ZIP creation uses native AES-256. Encrypted 7z creation also encrypts filenames. Encrypted 7z rejects link entries and names the installed helper cannot represent unambiguously.

Each selected archive gets its own extraction job. Extract Here and Extract To publish into the destination directly. Extract to Folder uses the archive name without its suffix. The Tools preference **Avoid redundant extraction folders** defaults to enabled and reuses a single same-named top-level directory. It has no effect on direct extraction.

Double-click a supported archive to browse it in the current tab. Up at the archive root returns to its containing folder. Archive members can be opened, copied, dragged to writable Places or folder tabs in the same window, or extracted with **Extract Selected…**. Exports start at the selected names and preserve the contents of selected folders. The clipboard offers ordinary file URIs from private temporary extraction, and Files keeps handed-off temporary files available until it exits. Browsing is read-only. Encrypted ZIP and supported encrypted 7z archives use the existing password prompt and keep the password in memory while the archive is open.

The backend and regression tests adapt Luciole's archive capability, writer, reader, input, support, XZ and RAR code from commit [26649c8264145ad527b3a13cf067f08cd4663f17](https://github.com/noctalia-dev/luciole/tree/26649c8264145ad527b3a13cf067f08cd4663f17) under the [MIT licence](../LICENSE). The 7z fixtures retain Luciole's original fixture provenance. The RAR reference fixtures retain their libarchive-derived redistribution notices in `tests/archive_rar_fixtures.h`.

Archive browsing also adapts Luciole's catalogue, member selection and related regression cases from [c91150b41dab0eac403800e8d005946d8f1fd68c](https://github.com/noctalia-dev/luciole/tree/c91150b41dab0eac403800e8d005946d8f1fd68c) under the same licence.
